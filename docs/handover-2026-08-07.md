## 1. What AnchorCore is

Local-first "company memory" layer: connect sources (folders, Jira) → classify into
entities with provenance → hybrid RAG Q&A with citations. Positioning: *"connect your
knowledge to any AI model."* Browser UI (React SPA) served by a single FastAPI process.

**Stack:** Python 3.12 + FastAPI + SQLite (sqlite-vec + FTS5) · React/Vite · Ollama
local models + BYO cloud OpenAI-compatible · packaged via PyInstaller (Windows exe +
macOS binary).

**Repo:** `git@github.com:Atsirkunov/anchorcore.git` (SSH; git identity set).
**This Mac** is the build/dev machine (Python 3.12, Node 20, Ollama + llama3.2:3b +
nomic-embed-text installed via Homebrew).

## 2. How to run / test / release

- Dev: `./start.sh` (or `start.ps1` on Windows) — venv, migrations, Ollama, backend :8000.
- Tests: `cd backend && .venv/bin/python -m pytest tests -q` → **82 tests, ~17s**.
  CI = pytest + `npm run build` on every push.
- Package: `./build.sh` (macOS) / `build.ps1` (Windows) → `dist/AnchorCore`.
- Release: bump `APP_VERSION` in `backend/app/routers/system.py:27` + FastAPI
  `version=` in `backend/app/main.py:109` → commit "vX.Y.Z" → `git tag vX.Y.Z` → push;
  `.github/workflows/release.yml` builds + attaches Windows exe & macOS zip to the Release.
- **The packaged app embeds the frontend at build time** — rebuild mandatory after any
  UI change (stale-build trap, B23/B25).

## 4. Key files / architecture map

- `backend/app/answer_engine.py` — the core: `ask()` → `_plan_tools` → `_execute_tools`
  (hybrid vector+FTS, `who_knows`) → `_fuse_evidence` (RRF) → `_graph_expand` (B32).
  All retrieval methods take an optional `source_ids` set (B15 scoping).
- `backend/app/pipeline.py` — ingestion: `_classify_and_store` (windowed, hash-skipped,
  concurrency-limited), `_distill_and_store` (B18), `_embed_item` (IDF gate), `_signal`.
- `backend/app/classifier.py` — per-doc-type extraction prompts (B26), `detect_document_type`,
  `classify`, `distill` (B18), rule-based fallbacks for all (CI-safe, no LLM in tests).
- `backend/app/models.py` — Source, IngestedItem, Entity, Relationship, Chunk (`kind`),
  Job, Project (+ `project_sources`). `db.py` sets `PRAGMA foreign_keys=ON` (critical).
- `backend/app/routers/` — `sources.py`, `entities.py`, `qa.py`, `projects.py` (B15),
  `settings.py`, `system.py`. `main.py` wires it all + serves the bundled UI.
- `frontend/src/` — App.tsx (tabs + header project picker), tabs/{Ask,Sources,Entities,
  Review,Settings,System}Tab.tsx, `api.ts`, `types.ts`.
- `backend/alembic/versions/` — migrations; head is `b15a0d1` (projects).
- `docs/` — product-plan (backlog + priorities), architecture (diagrams), packaging,
  releasing, mcp, rust-port, sample-dataset, v2v3-scope.

## 6. Caveats / gotchas (learned the hard way)

- **`PRAGMA foreign_keys=ON` must stay** in `db.py` — deletions depend on it.
- **CI macOS build must use Homebrew Python** (toolcache/python.org lack sqlite
  loadable extensions → packaged app crashes at startup). Don't revert `release.yml`.
- **validate-before-write in `create_project`** — a `db.flush()` before a 422 opened a
  write tx that stalled the whole suite 15–140s (DB write-lock contention with the
  background scheduler). Full suite is ~17s now; don't reintroduce eager flushes.
- **The suite runs without Ollama** — all end-to-end tests must pass degraded
  (rule-based classifier, keyword-only retrieval). Real-model probes are manual.
- **Shared test DB** across a module run (conftest uses one SQLite file) — scope
  assertions to your own source/entity ids, never assert global emptiness.
- **`observer.unschedule()` takes a watch, not a handler** (folder_watcher).
- **Stale packaged exe** = stale UI; always rebuild/re-tag after UI changes.
- Existing `~/.anchorcore` dev DB has extra test sources (samples, chat fixtures) —
  not a problem, just noise when demoing.
- sqlite-vec native lib is collected by `packaging.spec` (`*.dll`/`*.dylib`); the
  python.org/Homebrew split matters for CI, not local dev (Homebrew works).
