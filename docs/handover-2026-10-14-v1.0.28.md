## The stale-base incident (read this before the next session)

The feature was first built on a checkout last fetched Oct 12 (v1.0.21) while
remote had moved to 1.0.27 — six releases, 100 files. The original commit,
`1.0.22` version bump, and `v1.0.22` tag were all wrong and entirely local
(nothing was pushed). Recovery: original work preserved on branch
`r32-markdown-old` (commit `fe5f285`), bogus tag deleted, `main` reset to
`origin/main`, work re-integrated as Phase 38 (upstream already owns R32) with
migration renumbered 16 → 19. **Lesson: `git fetch` + compare with
`origin/main` before starting any multi-file work in this repo** — the sandbox
has no network, so a stale checkout looks exactly like a current one.

Environment notes from this session: the sandbox denies socket binds for
fresh binaries (3 known `TcpListener::bind` test failures, same signature as
upstream's log) and blocks the system temp dir (redirect `TEMP`/`TMP` to
`rust/target/tmp` for cargo/vitest). `tray-icon 0.26` was missing from the
offline cargo cache — fetched once via escalated `cargo fetch`, now cached.
`git` needs `-c safe.directory=...` (sandbox uid differs); `.agents/` is
read-only in-sandbox, so tree-wide operations (`reset --hard`) need
escalation. Never `git stash -u` here — it partially failed and dropped
untracked files into the stash (recovered via `stash@{0}^3`).
