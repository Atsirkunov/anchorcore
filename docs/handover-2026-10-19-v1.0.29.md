# Handover — 2026-10-19 — Phase 39 retrieval weighting → v1.0.29

## What landed

Phase 39 (11 items, built in 4 parallel waves on isolated worktrees, merged
locally, never pushed): deterministic retrieval ranking fixes from an
external review validated against the code. `Hit` carries leg provenance
(legs + ranks), applied decay, and a boosted flag, all exposed on search
hits and ask citations. Floor-only keyword matches take reserved tail slots
(`ANCHOR_KEYWORD_SLOTS`, default 2) instead of being locked out by the
TOC@1.0-vs-floor@0.5 fusion. Minimum-relevance gate returns empty evidence
unless some hit has a BM25 match, a boost, or cosine >= 0.50
(`ANCHOR_MIN_RELEVANCE_COSINE`, calibrated). Age decay floors at 0.8
(`ANCHOR_DECAY_FLOOR`). Filename boost matches whole tokens (exact basename
beats substring, shortest path wins, `v1.2`-style tokens never fire) at the
same `max + 1.0`, and the disputed-exclusion flag threads through it with
the stale/disputed filter moved before the top-k cut. Authority tiers sort
by (env, tier): Spec < Code < Config < Prose < Generated
(`ANCHOR_AUTHORITY_TIERS=0` disables). Suspect PDFs skip the TOC fence.
Contents pages no longer become ghost sections. New golden eval
(`tests/retrieval_eval.rs`, 12 docs / 16 pairs, per-leg recall table) calls
the production fusion path itself (`retrieval::orchestrate_fusion`, shared
with `orchestrate` — no mirror to drift). No schema migration.

Built as R38 on a stale 1.0.27 checkout (see below), reconciled onto
1.0.28, renumbered to R39 (remote owns Phase 38 = markdown chunking).
