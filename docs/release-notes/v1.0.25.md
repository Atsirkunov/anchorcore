# AnchorCore 1.0.25

Second round of retrieval fixes from agent testing on a large repo, plus
code/config indexing that treats code as code, manual per-document privacy
marks, and a system-tray app.

## Highlights

- **Search previews center on the match.** Result summaries and citation
  snippets now window on your query terms instead of showing the file's
  first bytes, so a hit for `routing-config.yml` shows the matching
  lines, not the header.
- **Live files reliably outrank test fixtures.** Ranking now prefers
  production files over test/sandbox/fixture copies regardless of score
  gaps (previously fixture scores were only halved, which never changed
  the order). Applies to plain questions, literal tokens like
  `ACME_TENANT_ID`, and code search alike. Questions naming test files
  still search them; opt out entirely with
  `ANCHOR_TEST_ENV_DEMOTE=1.0`.
- **Browse files by path.** New `GET /items?path_prefix=…` lists ingested
  files under a folder (e.g. `reportdata/`) with total counts and
  paging — no more probing item ids one by one.
- **Config files split by key.** YAML, JSON/JSONC and TOML configs are
  now sectioned by mapping key / table, so hits carry `treasury > acme`
  breadcrumbs and search matches structure, not one giant blob.
- **Code files no longer fabricate entities.** Code skips decision/action
  extraction entirely — implementation files surface as searchable,
  citable text instead of inventing process records.
- **System-tray app (Windows).** AnchorCore now runs from the tray with
  Show/Hide, a data-folder shortcut, and Quit (`--no-tray` disables it).
- **Privacy marks you control.** Automatic PII detection is gone: instead
  you mark whole documents as sensitive with one toggle (Sources and
  Entities views, or `PATCH /items/:id`). Source labels
  (internal/public/sensitive) still gate cloud providers as before.

## Fixed

- **One-line summary hits.** Internal section summaries no longer surface
  as search results — every hit is citable file bytes.
- **Repeated context blocks.** Adjacent hits no longer duplicate the same
  `[continued]` bytes; cut context is flagged with `content_truncated`.
- **Consistent content fields.** Item reads expose `content` just like
  search hits and citations (`text` still works).
- **Entity links.** Every entity now links to its parent item and chunk,
  including over MCP.

## Upgrade notes

- Migration 16 (new document privacy column) applies automatically on
  first launch; back up `anchorcore.db` first if cautious.
- **Re-sync your sources after upgrading.** A re-sync rebuilds config
  files into key sections, removes legacy code entities, and clears the
  old automatic PII flags (use Reclassify from a source row to force it).
- The `/pii/*` API and the PII settings tab are removed. If you relied on
  automatic flagging, mark sensitive documents manually after upgrading —
  restores from older backups import as unmarked.
- Cloud-provider gating for manually marked documents lands in a
  follow-up; until then, treat the mark as a label, not an enforcement.
