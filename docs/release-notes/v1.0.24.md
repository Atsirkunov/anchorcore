# AnchorCore 1.0.24

Retrieval fixes from agent testing on a large repo: live files win over
test fixtures, naming a file surfaces it, and large files no longer come
back as 68 KB single hits.

## Highlights

- **Live files outrank test fixtures.** Files under test, sandbox,
  staging, mock, fixture, example, sample or dev paths are demoted when
  the question doesn't ask about them, so the production file surfaces
  instead of same-named test rows. Opt out with
  `ANCHOR_TEST_ENV_DEMOTE=1.0`.
- **Naming a file finds it.** A filename in the question
  (`routing-config.yml`) now surfaces that file ranked first; search
  previously only matched file contents, never filenames.
- **Whole-file fetch.** New `GET /items/:id` returns a file's complete
  ingested text in one call (same provider gate as entities).

## Fixed

- **Whole-file 68 KB hits.** Section context around a match is now a
  ±2-chunk window capped at 8 KB (`ANCHOR_EXPAND_MAX_CHARS`) instead of
  the entire section — roughly 2k tokens per hit instead of 17k. Hits and
  citations carry `content_truncated` when context was cut.
- **Answer citations say when content was cut.** The truncation flag is
  plumbed through to citations and search hits, so agents know when to
  drill down via the item endpoint.

## Upgrade notes

- No migrations, no config changes, no action needed.
