# AnchorCore 1.0.27

Answers and search hits now cite your documents instead of the
one-line summaries extracted from them, PDF citations name their page,
and the privacy model is simpler: Sensitive is the only gated label.

## Highlights

- **Citations come from content, not paraphrase.** Search and Ask no
  longer let short entity summaries outrank the passages they were
  taken from — every citation is document content, so code, specs and
  prose all win on their own words. Recall is unchanged (benchmark
  identical before/after); entity lookup, related, conflicts and the
  review queue work exactly as before.
- **PDF citations name their page.** Breadcrumbs now carry page numbers
  (`Terms (p. 1)`, multi-page spans as `(pp. 2-3)`), and item reads
  carry a `pdf_quality` flag: `suspect` when the stored text still
  shows split-word damage, `repaired` when a repair pass fixed it.
- **Simpler privacy.** The per-item PII mark and the `pii` source label
  are removed from the app and the website — `Sensitive` stays the only
  gated label, and source labels remain the single trust boundary. The
  backend still accepts old marks and labels, so existing setups keep
  working.
- **Decisions and to-dos are extracted again.** The old document-type
  detection had collapsed every file to generic documentation, so real
  decisions arrived as plain notes — or nothing at all. Files now land in
  deterministic buckets (meeting/decision records vs reference docs) with
  strict per-bucket prompts: records may yield decisions and to-dos,
  reference stays notes-only. On the demo corpora this recovers 16
  decisions + 33 to-dos from 50 flat notes, with nothing lost.
- **Entities tab redesigned, Review folded in.** One "Needs a look" queue,
  a Possible-doubles strip showing both summaries with Merge/Not-doubles,
  plain-language labels (Decision / To-do / Note, Record / Reference /
  Code), dispute reasons with a readable History, and stated consequences
  on every action. The Review tab is gone — its flows live in Entities;
  the `/review/*` API stays for agents.
- **Exact-string search.** Search (and MCP search) gains `mode: "exact"`:
  a literal case-sensitive substring over stored content in document
  order, unranked — for when you know the precise string. Same trust
  boundaries as ranked search.

## Fixed

- **Reliability fixes from an independent code review**, including
  safer interrupted-sync bookkeeping plus scheduler and retrieval
  hardening.
- **Client-associated names scrubbed** from bundled fixtures and docs
  (see Upgrade notes).

## Upgrade notes

- **The 1.0.26 binaries are superseded by this release.** 1.0.26
  shipped before the cleanup pass above; upgrade to leave those builds
  behind. (1.0.27 zips are verified identifier-free at cut time.)
- `kind=entity` and `kind=distilled` search filters now match nothing:
  entities left the retrieval pool, so there are no entity rows left to
  match. The filter values are still accepted; entity data stays
  available through lookup, related, conflicts and review.
- **Re-sync PDF sources after upgrading** to gain page numbers on rows
  indexed before this release (the quality flag works retroactively
  without a re-sync).
- If you used per-item PII marks, switch to the `Sensitive` source
  label — the supported path going forward. Old marks are still stored
  and accepted, just no longer shown.
- Pending migrations apply automatically on first launch; back up
  `anchorcore.db` first if cautious.
- **Re-sync to pick up the new taxonomy.** Old rows keep their previous
  labels until re-sync; a re-sync (or force Reclassify) re-buckets them.
  Entities, conflicts, disputes and review state survive; only the labels
  and any re-extracted kinds change. New extraction never emits the old
  `document` kind (existing rows pass through).
- **Expect new Decision/To-do items after re-syncing meeting and decision
  files** — that's the recovery working, not new noise. Your review queue
  may gain entries; the Entities tab's Needs-a-look filter is the place to
  triage them.
- Reference files (specs, runbooks, policies, people docs) are notes-only
  by design — procedural steps arrive as notes, never assigned to-dos.
- Tag chips are removed from entity rows (they were an ungrounded
  client-side guess); breadcrumbs, sections and Whole doc keep provenance.
  They'll return only with a real backing endpoint.
