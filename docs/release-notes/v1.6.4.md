# AnchorCore 1.6.4

A fix for large libraries: AnchorCore 1.6.3 could sit on "Checking the
index" for an hour or more every time it started. This release makes that
step take seconds.

## Fixed

- **Large libraries start again in seconds.** On a library of a few
  gigabytes, 1.6.3 stopped on the upgrade screen's last step ("Checking
  the index") for a very long time, and did so on every start, not only
  after upgrading. AnchorCore looked up each document's search chunks
  without an index, reading the whole chunk table once per document. It
  now keeps an index for that. In our test with a 4.2 GB library
  (15,000 documents), 1.6.3 was still not ready after 10 minutes; 1.6.4
  was ready in 8 seconds on the first start and in 1 second after that.
- **Removing or rebuilding documents is faster too.** The same missing
  index slowed every operation that replaces a document's chunks, such as
  re-syncing a changed file or deleting a source, on big libraries.

## Also

- **The upgrade screen shows how long a step has been running** ("This
  step has been running for 3 min 12 s") once a step takes longer than
  10 seconds, so a slow step no longer looks frozen. The last step now
  says "Looking for documents to rebuild" while it checks which documents
  need new chunks, instead of staying on "Checking the index".

## Upgrade notes

- **The first start after upgrading adds the index** ("Migration 31:
  indexing chunks by document"). That takes about a minute on a large
  library; later starts are not affected.
- **If 1.6.3 is stuck on "Checking the index" right now:** quit
  AnchorCore and install 1.6.4. It is safe to quit at that step: every
  earlier upgrade step is already saved, and nothing in your library
  changes while it checks.
