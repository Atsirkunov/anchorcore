# AnchorCore 1.1.0

Indexing without a chat model, an agent mode for AI assistants,
Decisions and Actions lists, and a people-owned glossary — plus a
fix that unblocks indexing on upgraded databases.

## Highlights

- **Indexing no longer needs a chat model.** Document intake now runs
  with zero calls to a chat model by default: entity extraction uses
  built-in rules, and summarization is off unless you enable it. You
  can index a corpus on a machine with no model configured at all.
  (Opt back into model-assisted extraction per source with the new
  `extract_entities` setting.)
- **Agent mode for AI assistants.** A new answer mode (`llm_mode`)
  serves agents over MCP or plain REST: same scoping, gating, and
  ranking as search, but the server returns ranked evidence with
  content instead of composing prose — zero chat calls. The default
  `local` mode behaves exactly as before; switch modes in Settings.
  The Ask tab renders agent mode as an evidence view.
- **Decisions and Actions lists.** Two new views (and matching REST
  + MCP endpoints) list open actions by owner, overdue items, and
  decisions with their status — including superseded records. The
  Entities tab now opens on these views.
- **A glossary you own, instead of "Words to confirm".** The review
  queue of machine-guessed vocabulary is gone. Add terms yourself in
  the new Glossary admin, or mark one of your files as a glossary
  and AnchorCore parses it (CSV, Markdown tables, `CODE - meaning`
  lines). The only automatic rule left is initials-matching
  parentheticals (`Full Phrase (FP)`). Query-time acronym help from
  the answer model is now opt-in (`acronym_expansion=true`).
- **Safer embedding-model changes.** Every stored vector now carries
  its model's fingerprint. Switch models and stale vectors
  transparently fall back to keyword search while a backfill
  re-embeds them — instead of silently comparing vectors from
  different models. System status shows the active fingerprint and
  how many vectors are stale.

## Fixed

- **Upgraded databases can index again.** Databases carried over
  from the Python era kept an index definition whose engine no
  longer ships, and every chunk write failed with
  `no such module: vec0` — syncs found files but stored nothing.
  Upgrading to 1.1.0 removes the dead index automatically.
- **Extraction stops inventing records.** Decisions and action items
  now come only from record structure (decision headings, status and
  owner fields, action-item bullets, checkboxes) — never from prose
  sentences, table rows, or code blocks. Nothing is ever marked
  verified by the machine anymore; only people confirm records.

## Upgrade notes

- **Back up before upgrading** (System tab → Backup), as with any
  release carrying migrations. Migrations 21–24 run automatically:
  the dead-index removal, vector fingerprints, record columns, and
  the vocabulary cleanup.
- **Vocabulary:** machine-suggested rows are removed by the upgrade.
  Re-add any terms you relied on via the Glossary admin. Glossary
  files you mark are parsed on the next sync.
- **Decisions/Actions may show older entries** imported by the
  previous extractor (some marked verified by old rules). A cleanup
  that demotes and removes those follows in the next release; new
  extractions are always unverified until you confirm them.
- **No settings to change.** New settings arrive with safe defaults:
  rules-based extraction, agent mode off, acronym expansion off.
  Embeddings and search behave as before until you switch models.
