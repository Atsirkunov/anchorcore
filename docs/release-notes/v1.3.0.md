# AnchorCore 1.3.0

Indexing no longer uses a chat model, and the settings for one are gone.
Decisions and actions come only from how your documents are structured,
which already worked without a model, so there's one less thing to set up.

## Highlights

- **A shorter Settings page.** The "Classification (extracts entities)"
  section is gone: no classifier provider, model, API key or "Test
  classifier" button. It hasn't been needed since 1.1, when indexing
  switched to rules, but it still looked required. Settings now holds only
  what AnchorCore actually uses: embeddings for search, and an answer model
  if AnchorCore writes the answers rather than your agent.
- **Indexing makes no model calls.** Decisions and actions are read from
  record structure: `Decision:` headings, `Status:` and `Owner:` fields,
  ADR front matter, action-item lists and checkboxes. Ordinary prose isn't
  turned into "decisions". When you ask about something decided in a
  meeting, your agent reads the cited passages and finds it at question
  time, with no indexing cost and no stale guesses.
- **The System tab shows how entities are extracted** ("rules" or "off").
  It replaces the classifier-throughput card, which never showed any data.

## Removed

- **Opt-in LLM entity extraction** (`extract_entities=llm`). Its results had
  no owner, status, due date or record ID, so the decisions and actions
  lists couldn't use them. The setting still accepts `rules` (default) and
  `off`. If `llm` is still saved, it now behaves like `rules`.
- **Opt-in Q&A distillation** (`distill_enabled`). The Q&A snippets it
  created were never used in answers or search, so it cost model calls
  and changed nothing.

## Upgrade notes

- **One database migration runs automatically** on first start. It deletes
  any leftover Q&A distillation snippets, which were never used in search
  or answers. Your documents, entities and vectors stay as they are.
- **A saved classifier API key is erased** from the keychain at startup,
  since nothing reads it any more.
- **Backups:** older backup archives still import. Their distillation rows
  are skipped, and you may see "no local row … skipped" warnings for their
  vectors. Those warnings are harmless.
- **Renamed setting:** the embedding request timeout is now `embed_timeout`
  (default 60 seconds). If you set `ANCHOR_CLASSIFIER_TIMEOUT` to give slow
  embeddings more time, rename it to `ANCHOR_EMBED_TIMEOUT`.
- **For API and agent integrations:**
  - `GET /system/status` now reports `extraction.mode` instead of the
    `classifier` block, and `ollama.classifier_model` is gone.
  - `GET /health` no longer includes `components.classifier`.
  - `POST /settings/test-connection` no longer accepts `classifier`.
  - The `distilled` value of the search `kind` filter is gone.
- Use the 1.3.0 download. The app embeds its interface at build time, so
  older builds still show the classifier settings.
