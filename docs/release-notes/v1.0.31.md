# AnchorCore 1.0.31

Agent setup without the runaround, search that learns your
documents' vocabulary, and a fix for tracker syncs that failed
despite a saved API key.

## Highlights

- **The app serves its own agent skills.** Fresh installs fetch the
  setup and search skill documents over HTTP (`GET /system/skills/:name`,
  also from the System tab) — no git clone needed to connect an agent.
- **One-click skill install.** Each served skill has an Install button
  in the System tab that writes it into your agent's skills directory
  (confirm dialog names the target paths; existing files are backed up,
  never clobbered). Offered when MCP connect is blocked, never alongside
  a working MCP.
- **Answer setup is one verified flow.** Configuring answers — local
  Ollama or your own OpenAI-compatible endpoint — now ends with a real
  compose probe, and agent answers through MCP carry a plain-language
  `warning` whenever no model wrote them. Degraded output stays visible,
  never a silent fallback.
- **Search results stay diverse.** Final lists reserve slots per
  document kind, so a PDF or doc match can no longer be crowded out by
  code and decision records (`ANCHOR_TYPE_SLOTS`, default 2, `0`
  disables).
- **Keyword search learns your jargon.** A small curated synonym set
  (`cancel` ↔ `reverse`/`withdraw`, `CA` ↔ `Direct Debit`) plus
  automatic per-corpus extraction (parenthetical acronyms, glossary
  terms) expand keyword queries. Model-guessed pairs stay quarantined
  until a second document corroborates them or you approve them.
- **"Words to confirm" queue.** The Entities tab lists learned word
  pairs inline for approve/reject; rejections stay hidden for good,
  even across re-syncs.

## Fixed

- **Tracker syncs failed with "requires API key" despite a saved key.**
  Source credentials are stored in the OS keychain at creation, but the
  sync path only restored keys for fields still present as placeholders —
  and stored configs carry no secret fields at all. Every Linear, Jira,
  Google Drive, and authenticated generic-REST sync therefore ran without
  credentials and failed before contacting the tracker (REST basic-auth
  sources instead sent an empty password and failed remotely). Sync now
  resolves stored credentials for all secret-based connectors.
- **Drive's `access_token` alias is now keychain-backed.** Sources
  configured with that field name previously kept the secret in plaintext
  in the database and returned it unmasked. New sources store it in the
  keychain; existing ones are masked immediately and move into the
  keychain the next time the source is edited.
- **Section chunks match on their headings.** Vector search over
  sectioned documents now always includes the heading path, so a chunk
  that continues under "Reversal notifications" is found by those words
  even when they never appear in its own bytes. Breadcrumb paths also
  lost a stray leading separator.

## Upgrade notes

- Database migration 20 (vocabulary table) runs automatically on first
  launch. No action needed.
- **Older vectors refresh only on force re-sync.** Embeddings written
  before 1.0.28 lack heading prefixes and stay as-is — nothing
  re-embeds on its own. Reclassify a source to refresh its vectors and
  to build its vocabulary from already-indexed documents.
- The vocabulary builds as documents are (re)indexed. Approve/reject
  decisions survive re-syncs.
- Known gap: the vocabulary table is not in backup archives yet. After
  a restore, force re-sync rebuilds it (rule pairs fully, model pairs
  re-proposed for review).
- **No need to re-enter tracker keys.** Keys saved by earlier versions
  are intact in the keychain; just sync the source again.
