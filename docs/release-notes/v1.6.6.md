# AnchorCore 1.6.6

Large libraries upgrading from before 1.5.0 start much faster, and the
search skill offers a lasting fix for the sandbox question.

## Highlights

- **The search skill offers to stop asking.** The first time a sandbox
  blocks the skill, it asks once whether you want to allow AnchorCore's
  address (for example `127.0.0.1:8000`) in your sandbox settings. In
  Claude Code you do that with `/sandbox`. The skill never runs it for
  you: say yes and it tells you the exact address to allow, say no and it
  won't bring it up again this session.

## Fixed

- **The first start after upgrading a large, older library no longer
  sits on "cleaning up legacy entities" for minutes.** The one-time
  cleanup of old extracted entities (libraries last opened with a version before 1.5.0) looked
  up related rows one table scan at a time. It now uses indexes. In our
  test it went from about three minutes to well under a second, with the
  same rows removed.

## Upgrade notes

- **One new database step on first start: "indexing records".** It adds
  indexes so that deleting records (during that cleanup and when a
  document is reclassified) no longer scans the whole search index. It
  normally takes seconds. Nothing in your library changes.
- **Refresh the installed skill to get the new sandbox offer.** In the
  System tab, click **Install…** on the Ask docs skill and confirm.
