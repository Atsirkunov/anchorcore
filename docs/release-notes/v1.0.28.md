# AnchorCore 1.0.28

Markdown documents are now indexed by their structure — headings, code
blocks, tables and lists — instead of flat text, and citations and
search hits point at source line numbers.

## Highlights

- **Markdown that reads like markdown.** `.md` files now split into
  sections from real headings, with code blocks kept whole (language
  labels intact), tables split by row groups with the header repeated,
  and front matter (title, status, date) understood. Document titles
  come from the first heading, and a file's own table of contents is
  no longer indexed as content.
- **Line numbers on citations and hits.** Search results, answers,
  sections and outline entries carry the 1-based source lines they
  came from, so agents and readers can jump straight to the passage.
- **Answers match your headings.** What gets embedded now starts with
  the section breadcrumb, so a question using heading words finds the
  right section — while stored text stays exactly as written.
- **Outlines that scale.** The sections list and item outline accept a
  `depth` limit, so huge documents can be walked top-down instead of
  dumped whole.

## Fixed

- **`#` inside fenced code blocks no longer creates bogus sections.**
  A comment like `# not a heading` in a code sample used to split the
  document — fenced content is now fenced, always.

## Upgrade notes

- **Re-sync Markdown sources after upgrading** (or force Reclassify)
  to rebuild sections, line numbers and vectors. Previously indexed
  Markdown keeps working as before — old rows simply show no line
  numbers until re-indexed.
- Migration 19 applies automatically on first launch; back up
  `anchorcore.db` first if cautious. Backup archives from older
  releases import cleanly (missing fields default).
- ADR-style files (front matter with `status`/`date`, `ADR-NNN` names)
  now expose that metadata on their root section for agents to query.
