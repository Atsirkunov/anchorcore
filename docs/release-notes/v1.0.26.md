# AnchorCore 1.0.26

Search now returns the matching section with your hit marked, resyncs
skip unchanged files in seconds instead of re-reading everything, and
PDFs with broken word spacing are detected and repaired automatically.

## Highlights

- **Answers cite sections, not fragments.** Search and Ask now return the
  smallest section containing your match — with the matched passage
  marked and a breadcrumb path (`treasury > acme`) on every hit — so
  citations read as coherent chunks instead of stitched snippets.
- **Browse structure before bytes.** New `GET /items/:id/outline` returns
  a file's section tree with sizes, `GET /nodes/:id` walks parents,
  children and siblings, and search accepts `kind`, `symbol`,
  `path_prefix` and `env` filters (also over MCP) — built for agents
  that read structure first.
- **Fast resyncs.** Folder sync now fingerprints files by size and
  modification time: unchanged files are skipped without re-reading, and
  progress reads `514/514 · 3 changed` with an `N unchanged` line when
  done, so a no-op resync is visibly instant.
- **PDFs with split words repair themselves.** Word-exported PDFs whose
  fonts report zero glyph widths used to shred mid-word (`Cancellati
  ons`); AnchorCore now detects the damage per file and re-extracts with
  a flow-layout pass (real word gaps, tracked-spacing handling,
  paragraph breaks, hyphen joins), keeping whichever reads better. Clean
  PDFs are untouched, byte for byte. Repairs are logged and recorded as
  a System warning naming the file.
- **Documents keep their structure.** Word, HTML and ODT headings now
  become real sections, tables stay together (or split by row groups
  with the header repeated), and tables of contents are stripped instead
  of indexed as ghost content. Heading-less files fall back to paragraph
  windows rather than one giant blob.

## Fixed

- **Chunks no longer cut mid-word or mid-sentence.** Overlong passages
  now break at sentence ends, else word boundaries — no more `…tions
  and…` edges in citations and search hits.
- **Page numbers and repeated headers in chunks.** Running heads, footers
  and page-number lines (`42`, `Page 3`, `- 12 -`) are stripped before
  chunking, so they stop polluting search and embeddings. Code and
  config files are exempt (their splitters read indentation).

## Upgrade notes

- Migration 17 (file fingerprints) applies automatically on first
  launch; back up `anchorcore.db` first if cautious. The first sync
  after upgrading re-reads every file once to record fingerprints, then
  resyncs go fast.
- **Re-sync your sources after upgrading** to rebuild chunks with the
  new cleaning and section shaping — use Reclassify from a source row to
  force it, which also repairs any PDFs that were indexed with split
  words.
- Search hits and citations carry two new fields, `section_id` and
  `breadcrumb`, and contexts are section-shaped instead of
  neighbor-stitched; everything else in the API is additive, nothing
  was removed.
