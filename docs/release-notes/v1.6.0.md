# AnchorCore 1.6.0

Sensitive content is now gated by default on every surface: one Sensitive
mark per source (or per document) keeps those passages away from cloud
providers and agents unless you say otherwise, while the app itself always
shows you everything. Agents also get proper read APIs — line windows,
section text, and item reads over REST and MCP — and stopping a running
job finally stops the job you meant.

## Highlights

- **Sensitive means Sensitive, everywhere.** The old separate PII label is
  gone: each source is either ordinary, public, or Sensitive, picked in the
  source form, with an optional per-document mark through the API. Sensitive
  passages are withheld from untrusted cloud providers and from agents
  (MCP, skill, API) by default — single reads answer 403, lists and search
  drop the rows — while the app UI always shows you everything. The public
  scope (`/qa/public`, `public_only`) excludes Sensitive items no matter
  what. Every withholding is recorded in the System tab's event log.
- **Agents can read, not just search.** New read APIs over REST and MCP:
  whole-file and line-window item reads, section text in document order,
  section/tag chunk lists, and entity reads with context (`list_items`,
  `get_item`, `get_outline`, `get_entity`). All of them enforce the same
  Sensitive gate as search.
- **A setup wizard that fits your machine.** The first-run wizard now
  recommends a local answer model sized to your RAM, lets agent-mode users
  pick the MCP or skill channel, and falls back to the built-in embedder
  when Ollama is down.
- **Stop the job you mean.** Every running or queued job has its own
  labeled Stop control (kind + id + source) in the Sources row and the
  System tab, plus a header badge that leads there. Stopping lands within
  one provider call and reports how many documents were kept.
- **Faster re-syncs.** Tag matching now runs over an indexed per-pass
  cache (measured: the tags phase of a big re-sync went from ~73 s to
  ~4 s), and files with no extractable text no longer re-ingest on every
  sync.
- **Tags you can trust.** Single-word tags no longer merge into whichever
  tag shares their hash bucket, so the tag list grows with your vocabulary
  instead of stalling near 768, and the tag-reuse threshold finally reads
  the database the app is actually running on.
- **Local answers without the memory spike.** Chat calls to a local Ollama
  now pin the context window instead of letting Ollama auto-size it, so a
  3B model no longer loads gigabytes it will never use.
- **Bigger backup imports.** The import size cap is now 2 GiB.

## Fixed

- The folder picker no longer renders empty stripes in Chromium-based
  browsers: rows keep their height and labels truncate inside them.
- Cancelling no longer picks the wrong job when several are active, and a
  second cancel (or one racing completion) answers 409 instead of
  corrupting job state.
- Files whose text extracts empty no longer re-ingest on every sync.

## Upgrade notes

- **Sources labeled `pii` become `sensitive` automatically** on first
  start (database migration 29). The per-document mark moved to
  `PATCH /items/:id {"sensitive_override": true}` (`null` clears it);
  the old `is_pii` field answers 400 naming the new one, and old backup
  archives import with the mapping applied.
- **Agents may see less than before.** Whole-file reads, entity reads and
  chunk lists are now gated for agents under an untrusted provider (they
  were open), and public scopes exclude Sensitive-marked documents even
  with a trusted provider. If your agent suddenly misses content, that is
  the gate working: approve the provider (per-destination opt-in switches
  are coming in a later release) or read the same content in the app, which
  is never gated.
- Tag counts grow with your vocabulary now (see above); links written
  under the old merging scheme stay until the item is re-processed.
