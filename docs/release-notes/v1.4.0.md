# AnchorCore 1.4.0

Diagrams and images are now part of your company memory. Flow diagrams are
indexed as readable text, and the pictures inside your documents are stored
with them, so a cited answer can show the image it came from. Indexing still
makes no model calls.

## Highlights

- **Diagrams are searchable.** draw.io (`.drawio`, `.dio`), Excalidraw
  (`.excalidraw`, `.excalidraw.json`, `.excalidraw.svg`), Visio (`.vsdx`,
  `.vsdm`) and the text in SVG files are read as flows: each frame becomes a
  heading, shapes are listed in reading order and arrows become lines like
  `Review → Approve: on sign-off`. Ask "what happens after review?" and
  the answer cites the diagram.
- **Miro boards as a source.** Add a Miro source (an access token plus
  board IDs or a team ID) and its boards are indexed the same way. Boards that haven't changed since the last sync are
  skipped.
- **Images are kept with your documents.** Pictures linked from Markdown
  and HTML, image files in a folder, images inside Word, PowerPoint and
  OpenDocument files (folder and Google Drive), and pictures embedded in
  PDFs are all stored in AnchorCore's own database. Search hits and
  citations list the images next to the passage they belong to, and source
  cards in Ask show thumbnails. Charts that a PDF draws as vector graphics
  are not images and are not stored.
- **Your backups include the images.** An export restores every image even
  when the original folder or Drive file is gone.
- **Agents can see the images.** Over MCP, `get_asset` returns the image
  itself; over REST, `GET /media/:uid?format=json` returns the same thing.
  Both follow the same source-label rules as search, and refuse images over
  1.5 MB with the size and a link instead.
- **Unplaced images.** A picture with no surrounding text to be found by,
  such as a bare slide or an image-only PDF page, appears under Sources →
  Unplaced images. Write a caption, optionally point it at the document or
  section it belongs to, or hide it. Captions are written by people only;
  AnchorCore never guesses one. A captioned image answers questions through
  its caption.
- **No more duplicate syncs.** A source runs at most one sync at a time.
  A second sync request is refused with the running job's ID (HTTP 409)
  instead of queuing a copy, and background triggers fold into it.
- **Large files index in seconds, not hours.** Deciding which passages to
  embed used to slow down sharply as a file got bigger: a 2 MB file with
  8,401 passages never finished. It now takes about a second, and tagging
  dropped from 21 s to 2 s. The whole file indexes in about 90 s with a
  local Ollama, most of it spent on embeddings.
- **A new story in the sample company.** The bundled sample and the
  website's `sample.zip` now follow an Instant Payments project (outgoing
  payments only), and the example questions changed with it: "What was
  decided about instant payments, and why?".

## Fixed

- **Restoring a backup no longer loses document structure.** Imports
  dropped the link between each passage and its section, so restored
  documents answered as one flat block until re-synced.

## Upgrade notes

- **One database migration runs automatically** on first start. It adds the
  image tables. Nothing existing changes.
- **Re-sync to pick up images and diagrams in files you already indexed.**
  Folder sync only re-reads files that changed, so press **Reclassify** on a
  source (or `POST /sources/:id/reclassify`) to store the images in its
  existing documents and PDFs. New and
  edited files get them automatically.
- **Image size cap.** Images over 20 MB are recorded (name, size, where
  they appear) without their bytes. The cap is `asset_max_bytes` and can be
  changed through the settings API or environment; there is no field for it
  in Settings yet.
- **Using the sample company?** Re-sync it to get the new files. The old
  sample files are removed from the index on that sync.
