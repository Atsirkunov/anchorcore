# AnchorCore 1.4.1

Syncing and reclassifying are much faster: tagging used to slow down as your
collection grew, and on large collections it could cost several seconds per
file. It now takes milliseconds, whatever the size.

## Highlights

- **Reclassify and sync run up to ~40% faster.** Tagging a large file dropped
  from about 10 seconds to half a second on the measured corpus, and unlike
  before, it no longer gets slower the further a long run gets. A run that
  crawled at a dozen seconds per file should now move at the speed of its
  embeddings instead.

## Fixed

- **Tagging re-read a setting once per existing tag.** Every new tag opened a
  throwaway database connection for every tag already stored, so the cost grew
  with the collection. The setting is now read once per file. Stored tags and
  results are unchanged, only faster.

## Upgrade notes

- **No migration, no behavior change.** Update, restart, and re-run; a sync or
  reclassify that is already running keeps the old speed until you restart the
  app.
- **Long runs and sleep:** a laptop that falls asleep pauses syncing entirely
  (nothing progresses while asleep). For a multi-hour first sync or
  reclassify, keep the machine awake until the job finishes.
