# AnchorCore 1.5.0

Search no longer needs Ollama. AnchorCore can now embed with a built-in model
that runs inside the app, re-syncing an edited document skips the work that
didn't change, and a "Report issue" button turns a wrong answer into a
shareable, redacted bug report.

## Highlights

- **Built-in embedding model — no Ollama needed for search.** Press
  **Download built-in model** in the setup wizard or in Settings →
  Embeddings (about 550 MB to download, about 275 MB on disk). It is the same
  `nomic-embed-text` v1.5 model Ollama serves, running inside the app (Metal
  on macOS, CPU on Windows and Linux), so its vectors are identical: switching
  between the two never re-indexes anything. When Ollama is running and has
  `nomic-embed-text`, AnchorCore keeps using it, because it indexes large
  folders faster; the built-in model takes over when Ollama is not there.
  The download only happens when you ask for it, is checked against pinned
  checksums, and resumes if interrupted. Offline? Copy the three model files
  into the folder the card shows and press the button. Headless:
  `anchorcore embed-model fetch`. New setting `embed_provider`: `auto`
  (default), `builtin`, or `ollama`.
- **The Team image embeds out of the box.** The Docker image now ships the
  built-in model, so hybrid search works without any Ollama. If the host runs
  Ollama, `.env.example` now marks it as trusted so sensitive sources still
  embed through it.
- **Small edits re-sync fast.** When a document changes, every passage whose
  text didn't change keeps its stored vector. Fixing one character in a large
  file now re-embeds only the passages around it (measured: the embedding step
  went from 136 s to under a second on a 4,500-passage file).
- **Report a wrong answer.** Every answer in Ask has a **Report issue** link
  that downloads a diagnostics file for that query: which search legs found
  which results, their ranks and scores, index counts and versions. It
  contains no document text, titles, paths, settings or secrets (documents
  and sources appear as pseudonyms), only your question, so you can send it
  to support after a glance. Agents get the same file from
  `GET /system/report`.
- **Strong keyword matches are no longer buried.** A passage that matches
  several of your query's words strongly (often in a PDF) can now rank above
  weaker matches from higher-authority sources instead of being held below
  them.
- **Meeting notes with only an "Action items" section count as records.**
  Their action items now show up under Actions.

## Fixed

- The folder watcher no longer re-scans every folder every second; it reacts
  to file events and double-checks once a minute (`ANCHOR_WATCH_FALLBACK_SECS`).
  Idle CPU is near zero, and removed or disabled sources stop being watched.
- Starting a second copy of the app no longer opens a browser tab onto the
  first one; it exits with "is AnchorCore already running? try --port".
- MCP **Connect** now works when the app runs with a custom `--data-dir`: the
  client entry gets the same `--data-dir`, so `anchorcore mcp` finds the app.
- macOS: the menu-bar icon is now a monochrome glyph that follows light and
  dark menu bars, and remembers where you ⌘-dragged it.
- Large documents no longer hold the database write lock while being cleaned
  and split into passages.

## Upgrade notes

- **One-time entity cleanup, with a backup first.** On first start, 1.5.0
  copies your database to `exports/safety-backup-pre-r45.10-<time>.db` (never
  deleted automatically), then removes decisions and actions that older
  versions extracted with a language model or from documents that aren't
  records, and marks the remaining old ones as unverified (verified means a
  person confirmed it). The counts are in the System tab's event log
  (component `migration`). **Run Reclassify on each source afterwards** to
  rebuild decisions and actions from document structure.
- Embedding batches can now overlap for remote embedding APIs
  (`ANCHOR_EMBED_CONCURRENCY`, default 2). Local Ollama speed is unchanged.
- The app binary is a few MB larger (the built-in model's runtime). The model
  itself is downloaded separately, only when you ask.
