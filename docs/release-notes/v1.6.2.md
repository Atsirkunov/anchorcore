# AnchorCore 1.6.2

Your agent now understands questions about your documents in your own words,
the search skill has a shorter name you can change, and the System tab's
errors list can finally be cleared and filtered.

## Highlights

- **Ask in your own words.** Agents pick AnchorCore up for questions like
  "what did we decide about refunds?", "who owns the payout migration?" or
  "where is onboarding documented?" — no need to say "AnchorCore". This
  works over MCP (the server now tells agents what it is for) and through
  the skill. Decision questions go to the decision log, owner and open-work
  questions to the action tracker, everything else to search, and the agent
  reads the passage before citing it. When nothing indexed matches, it says
  so instead of answering from general knowledge.
- **The search skill is now `ask-docs`, and you choose its name.** Call it
  with `/ask-docs what did we decide about refunds?`. When you install it
  (System tab, the welcome wizard, or the setup skill), you can pick a
  different handle, such as `/kb`. Installing under a new name retires the
  old copy, so your agent never runs two.
- **Errors & warnings you can clear.** In the System tab:
  - Dismiss one row, or clear everything shown, and bring it back any time
    under "Show dismissed".
  - Filter by level, component and source.
  - Repeats of the same problem collapse into one row with a count and when
    it was first and last seen, and long details expand on click.
  - Info events (mostly the log of agent calls) are hidden by default.

## Fixed

- **The component filter on the errors list missed most components.** It
  offered a fixed list; it now lists the components that actually have
  events.
- **The skill could ask you to loosen your sandbox when AnchorCore simply
  wasn't open.** It now tells the two apart: "open AnchorCore" when nothing
  is listening, and one question asking for access to just the app's local
  address when your agent's sandbox blocks it. It never bypasses the
  sandbox without your yes.

## Upgrade notes

- **Reinstall the search skill** to get the new name and behavior: System
  tab → Agent skills → Install… (or ask your agent to run the setup skill).
  Your existing `anchorcore-search` copy keeps working until then; the
  reinstall retires it (renamed to `SKILL.md.anchorcore.bak`, not deleted).
  Restart your agent afterwards.
- **MCP users need nothing new:** restart your agent to pick up the new
  routing.
- **One small database update** runs at first launch (a column on the
  events table); it takes moments, whatever the database size.
- **Dismissing never deletes.** The events table is also the record of
  which questions agents asked, so cleared rows stay stored; they are
  just hidden.
