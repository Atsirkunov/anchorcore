# AnchorCore 1.0.22

Answers and search results carry more of what agents need: file
provenance on every hit, full text on request, and an embedding backlog
that drains itself.

## Highlights

- **Search hits name their file.** Every hit now carries the item title
  and file path (or section breadcrumb), so agents can cite sources
  precisely.
- **Full text on request.** Both search and answers accept
  `include_content`, returning complete chunk bytes instead of previews;
  over MCP, long chunks are capped with an explicit `content_truncated`
  flag rather than silently cut.
- **Longer previews by default.** Summaries grew 200 → 500 characters and
  answer snippets 300 → 500, and the citation count is tunable
  (`ANCHOR_CITATIONS`, default 5).
- **In-app update check.** The System tab shows when a newer release
  exists (manual check; optional startup check, off by default).

## Fixed

- **Stuck embedding backlog.** A scheduled backfill now embeds chunks
  that ingest skipped, so `pending_embeddings` drains to zero instead of
  sitting still with nothing in the logs.
- **Release builds wrote no log file.** Windowed builds now log to
  `{data_dir}/anchorcore.log` (10 MB × 3 rotating) like dev builds do.
- **Sync progress counts.** Re-syncs show files/total (N/N) instead of
  overwriting the total with the changed-items count.

## Upgrade notes

- No migrations, no config changes, no action needed.
