# AnchorCore 1.0.29

Search results get a major relevance overhaul: exact matches always get
room, authoritative documents outrank generated files, weak matches
honestly return nothing — and every result now shows why it ranked where
it did.

## Highlights

- **Exact matches always surface.** A keyword-only match used to lose to
  every section-search hit whenever section search returned enough
  results. Reserved result slots now guarantee top keyword matches a
  place in the final list.
- **Authoritative sources rank first.** Results order by file class:
  ADRs and specs above source code, code above config, everything above
  generated files, vendored code and lint configs. Test and fixture
  files still sink below live ones as before.
- **Old but authoritative docs stop being buried.** Age decay now floors
  out instead of fading to zero, so a two-year-old ADR can still beat
  fresh trivia.
- **Honest "not found".** When nothing genuinely matches, search returns
  no hits and Ask says so — instead of filling all 8 slots with
  plausible-looking noise.
- **Every hit explains itself.** Search hits and citations show which
  search methods matched and at which rank, how much age decay applied,
  and whether the hit came from a filename mention.
- **Filename search finds the right file.** Naming `service.go` now
  surfaces `service.go` even next to `myservice.go`, and version labels
  like `v1.2` no longer trigger file search by accident.
- **Damaged PDFs stop hiding their content.** Documents whose text
  extracted poorly are now searched directly instead of through their
  unreliable section summaries.
- **No more ghost sections.** A document's table-of-contents page no
  longer becomes a set of near-empty sections next to the real ones.

## Fixed

- **Disputed items could surface through filename search.** Naming a
  file bypassed the disputed-content filter; the filter now applies on
  that path too, and exclusions no longer eat result slots.
- **Contents pages polluted outlines.** Covered above — kept as text,
  never as sections.

## Upgrade notes

- No database migration and no re-index required — ranking changes apply
  immediately to existing corpora.
- **Expect different result ordering** — that is the point of this
  release (authority tiers, keyword slots, relevance gate). If runbooks
  ever lose wrongly to config files, set `ANCHOR_AUTHORITY_TIERS=0` to
  restore pure score ordering and report the query.
- New tuning knobs (all optional, all live without restart):
  `ANCHOR_KEYWORD_SLOTS` (2), `ANCHOR_MIN_RELEVANCE_COSINE` (0.50),
  `ANCHOR_DECAY_FLOOR` (0.8), `ANCHOR_AUTHORITY_TIERS` (on). See
  `docs/guides/retrieval-tuning.md` for the symptom-to-knob table.
- Contributors: `cargo test -p anchorcore --test retrieval_eval`
  prints the per-leg recall table — add failing queries as pairs before
  tuning fusion.
