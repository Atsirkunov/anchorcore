# AnchorCore 1.7.0

The app has a new layout — Library, Agents, and a Settings rail with
everything reachable by link — and a whole-app reliability pass means
operations that used to report success while doing nothing now fail
loudly instead.

## Highlights

- **New layout: Ask · Library · Records · Agents · Settings.** The
  Library (was Sources) lists your sources first, each with its own
  page showing documents and recent jobs. The Agents tab gathers
  everything about connecting a coding agent: one-click MCP setup,
  the skill files for when MCP is blocked, and the switch for whether
  agents may read Sensitive content. Settings is now a rail of
  sections — Answers, Search, Sensitive sharing, Glossary, Backup,
  Updates, Status & logs, Appearance, Advanced — with the old System
  tab folded into Status & logs.
- **Every tab has an address.** Tabs live in the URL hash, so reload,
  Back, bookmarks, and links from warnings all work. Old `#/sources`
  and `#/system` links redirect to their new homes.
- **Ask keeps its conversation.** Switching tabs no longer erases your
  questions and answers, and the project scope moved from the header
  into Ask itself, next to a plain "Public sources only" option.
- **No answer model, no panic.** Without a working answer model, Ask
  now shows the matching passages as evidence cards with one calm
  setup hint — instead of four warnings and raw markdown cut off
  mid-word.
- **Calmer look.** Dark mode is a neutral cool black instead of warm
  brown, links are ink with oxblood reserved for citations ("this is
  sourced"), and small caps labels are plain text. The website now
  opens in Light with the theme switch in its footer.
- **Starter questions from your own records.** The sample questions
  only show for the bundled sample corpus; on your own library Ask
  suggests questions built from your newest decision and newest open
  action — and clicking one runs it.
- **Quieter failures, fixed.** A full review of error handling: source
  delete and update are now all-or-nothing (a failed write answers
  500 instead of 200 with half the change applied), marking a
  document Sensitive, renaming records, and saving settings all
  report real failures, and the job queue no longer loses finishes.
  The Sensitive gate now fails closed: if a label can't be read, the
  content is treated as Sensitive.
- **RTF files read correctly**, including non-English text — and any
  RTF indexed before this release is automatically re-read once on
  its next sync, so garbled text repairs itself.

## Fixed

- **RTFs with accented or non-Latin text came out garbled**
  ("Café" indexed as "CafÃ©"); underline and `uc` control words also
  misread. Non-English RTFs now index as written.
- **Ask timed out after 30 seconds** while the server was still
  working (it allows two minutes or more). Ask now waits up to three
  minutes and only says "cancelled" when you actually cancel.
- **Every write failed with 403 until reload after a server
  restart.** The app now refreshes its expired token and retries
  once, on its own.
- **Marking a document Sensitive could answer 200 while leaving it
  unprotected.** It now succeeds or fails as one unit, loudly.
- **Stale claims corrected.** The website no longer advertises the
  old `pii` label (there is one Sensitive concept plus a
  per-document mark), the MCP card lists all the tools, backups no
  longer mention the removed review queue, and footers no longer say
  "v1 local".

## Upgrade notes

- **One new database step on first start: "adding extractor
  generations".** It stamps each document with the version of the
  reader that extracted it. Instant; nothing in your library changes.
  Afterwards, RTFs indexed by older versions re-extract once on
  their next sync — only the file read is repeated, and files whose
  text is unchanged are left alone.
- **The `/review/*` API is removed.** The review queue was dropped
  earlier; record disputes and restores live in the Records tab and
  the `/decisions` + `/actions` endpoints. Agents still calling
  `/review/*` need to move.
- **`GET /sources` now includes each source's config** (secrets
  masked), so clients no longer need one request per source.
