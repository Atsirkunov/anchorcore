## Session start

- **Check git before work**: `git fetch origin`, compare `HEAD` vs `origin/main` (`git log --oneline HEAD..origin/main`, `git tag --sort=-v:refname | head`). Releases and other sessions move `main` under you (the weighting phase was once built as R38 on a stale base and had to be renumbered to R39). If behind, reconcile before writing code, not after.

## What this is

Local-first "company memory": connect sources (folder, Jira, Linear, Drive, REST) → classify into entities with provenance → hybrid RAG Q&A with citations. One Axum process serves a React SPA. Stack: **Rust (Axum) + SQLite (sqlite-vec + FTS5)** · React/Vite · Ollama local + BYO cloud OpenAI-compatible. Ships as a single binary (`frontend/dist` embedded); `hosting/` is the one-container Team image (R19.1). Current version: see `docs/release-notes/`. Repo: `git@github.com:Atsirkunov/anchorcore.git`.

## How to run / test / release

- Dev: `cargo run -p anchorcore -- --port 8000 --data-dir ~/.anchorcore` (migrations, watcher, jobs).
- Rust tests: `cargo test -p anchorcore` green + `cargo check` clean (strict: `RUSTFLAGS="-D warnings"`; clippy `unwrap_used` is allowed crate-wide). Lizard gate: no new warnings vs the accepted baseline (listed in `rust/AGENTS.md`). The API contract tests (`tests/api_*.rs`, black-box HTTP against a spawned binary) run inside `cargo test` — no separate conformance step.
- Frontend: `cd frontend && npm run build` (tsc + vite; must pass before a UI change is done).
- Team image: `docker compose -f hosting/docker-compose.yml up --build`. License gate `ANCHOR_EDITION=team` (`license.rs`; issue via `python scripts/make_license.py`).
- CI skips docs-only pushes (`ci.yml` `paths-ignore`: root `*.md`, `docs/**`, `rust/*.md`, `rust/docs/**`); tags always run everything. Don't widen it to markdown the build/tests read (skills, `sample*/`, eval fixtures).
- Release: `docs/releasing.md` is the checklist (bump `rust/Cargo.toml` → draft notes → tag `vX.Y.Z` → push). CI builds `AnchorCore-{windows,macos,linux}.zip` on every `v*` tag (ad-hoc signed, not notarized).
- **The binary embeds `frontend/dist` at build time** — after any UI change `npm run build` + `cargo build --release`, or the exe ships stale UI.

## Architecture map (`rust/crates/anchorcore/src/`, shipped source of truth)

- `main.rs` — wiring + routes (frontend fallback stays last); binds the port before tray init so a second instance exits before planting a zombie icon.
- `db.rs` — `open_db`/`init_db`, `PRAGMA foreign_keys=ON`, WAL; migrations in `migrations/*.sql`, registered in `db.rs`.
- HTTP areas: `sources.rs` `entities.rs` `records_api.rs` (R45.9 `GET /decisions` + `GET /actions`; MCP `decisions`/`actions` wrap them) `jobs.rs` `projects.rs` `items.rs` `review.rs` `settings.rs` `system.rs` `sections.rs` `tags.rs`, plus `auth.rs` `security.rs` `health.rs`. Same paths/shapes/`detail` errors as the archived Python routers. DB work goes through `spawn_blocking` + `with_db`/`run_db` (`pipeline.rs`); never hold `Connection` (`!Send`) across `await`.
- Retrieval: `answer.rs` (`ask`/`search` orchestration, follow-up rewrite, answer generation) + `retrieval.rs` (legs, fusion, slots, gates — see below).
- Ingest: `pipeline.rs` (`ClassifyCtx` phases: classify windows → store → summaries/tags) + `chunking.rs` (prose/code/config dispatch) + `markdown.rs` + `extract.rs` (all file formats) + `diagram.rs` (R46.1 normal form: frames/nodes/edges → markdown for `markdown.rs`; parsers set frame membership) + `idf.rs` (embed signal gate) + `hashing.rs`.
- Models: `classifier.rs` (model-free since R45.18 — record-structure rules via `records.rs`; `extract_entities` = `rules` (default) | `off`, anything else reads as `rules`; `code` skips extraction entirely; there is no classifier model, key or test-connection) + `embedder.rs` (IDF-gated; raw vs embed inputs stay split; timeout `embed_timeout`) + `embed_fp.rs` (vector provenance/families, R45.5) + `ollama.rs`.
- Vocabulary: `vocab.rs` (migrations 20 + 24; people-owned glossary + one initialism rule, all active, no proposals) + `glossary.rs` (`/glossary` CRUD) + `query_expand.rs` (local-mode query-time acronym expansion).
- Secrets/settings: `secrets.rs` (OS keychain + per-key `secrets.enc.<sha256>` file fallback) + `settings.rs` (env default, DB overrides win, read at call time, empty means unset).
- Ops: `watcher/` + `scheduler.rs` (source reload, embedding backfill) + `jobs.rs` (`MAX_CONCURRENT=2`, pending queue).
- Shipping/integrations: `backup.rs` + `cli.rs`, `license.rs`, `frontend.rs` (embedded UI), `tray.rs`, `mcp.rs` (+ `mcp_setup.rs`), `skills_setup.rs`, `fsbrowse.rs`.

## Retrieval pipeline (the core logic)

`ask()`: scope `source_ids` → `rewrite_followup` (pronoun-only) → shared `orchestrate_fusion` (TOC-or-flat legs → RRF → age decay → cap/dedupe → live-first → authority tiers → cut + type slots → keyword slots → filename boost → relevance gate) → `generate_answer` with citations (agent mode stops before generation, R45.2). There is no who-knows leg or graph expansion (deleted in R45.9 — they had no production callers); ownership and supersession are `GET /actions` / `GET /decisions` (`records_api.rs`). Living docs, not this file, carry the details: `docs/guides/retrieval-tuning.md` (knobs + what each fix did) and `docs/guides/retrieval-weights.svg` (diagram); TOC mechanics in `docs/guides/hierarchical-toc.md`.

Rules that must not break:
- RRF: `score = Σ weight/(60+rank)` over ranks, never raw scores — demote/reorder after fusion, not before.
- `status_ok` (`retrieval.rs`) is the single stale/disputed hook for every path (vector, FTS, fallback, decisions/actions listings). New status exclusions go there, nowhere else. `ANCHOR_QA_EXCLUDE_DISPUTED` toggles disputed.
- Every retrieval fn takes `source_ids` (`None` = everything). Hits carry leg provenance + scores in RRF range (agent API surface — never raw BM25 next to RRF).
- Golden eval: `cargo test -p anchorcore --test retrieval_eval` — fused recall must stay 1.00 on every pair (`tests/eval_data/README.md` is the fixture discipline). It models leg plumbing with hash embeddings, not model quality.

## Feature workflow (Rust-only)

1. Schema: `db.rs` + migration `N+1` in `migrations/*.sql` (register it; one-shot backfills go in real `M::up` SQL, never `ensure_columns`; extend the v10-sim migration test the same way). No `backend/` mirror — it is archived.
2. API: handler + route in `main.rs` (frontend fallback stays last).
3. Wire into `retrieval.rs`/`pipeline.rs` if it affects retrieval/ingestion.
4. Frontend: `types.ts` + `api.ts` + tab component; `theme.ts` tokens (CSS vars from `theme.css`, light + dark), no inline hex; `npm run build` must pass (then re-`cargo build --release` to embed).
5. Gates: `cargo test` + `cargo check` green, lizard no-new-warnings, golden eval green; extend `tests/api_*.rs` when touching shared API behavior.
6. Docs in the same commit (`rust/BACKLOG.md` row → DONE, `docs/` update, decision in `rust/docs/decisions.md` when you chose between real options).
7. CCN ≤ 15 per function (lizard): split orchestrators into named phase helpers, guard clauses over nesting, `run_db` for blocking DB work.

## Gotchas (live contracts — don't reintroduce)

- **`PRAGMA foreign_keys=ON` must stay** (`db.rs`; deletes rely on it — entities used to get `item_id` NULLed on source delete).
- **Validate before opening a write tx** (SQLite single-writer): a validation error after a write starts stalls everything behind the scheduler. Project CRUD is the good pattern: validate sources first, then write.
- **The suite runs without Ollama** — all tests must pass degraded (rules classifier, keyword-only retrieval). Real-model probes are manual. On a dev Mac run Rust tests with `ANCHOR_SECRETS_NO_KEYRING=1` or two no-model-key tests read your real keychain key and fail (environmental, CI-clean).
- Secrets: never log/return raw tokens — `GET /sources/{id}/config` masks secrets as `***set***`, logs redact them.
- **Stored source configs carry no secrets** — create/update strips them into the SecretStore, so the
  DB config has no `api_key`/`token` key at all. Sync-time `resolve_config` (`pipeline.rs`) must fill
  absent fields from the store, not just `***set***` placeholders (those only exist in GET responses).
  Resolving placeholders-only broke every API-connector sync with "requires api_key (or token)".
- **SecretStore fallback is per-key** (`secrets.enc.<sha256(key)>` files) — the old single-blob design made `delete(key)` wipe *every* stored secret. `store_source_config` treats `***set***`/absent as "leave unchanged", explicit `""` as "clear".
- **Retrieval is scan-backed — no vec0 is linked:** `sqlite-vec` is not a dependency, so `vec_chunks` is a plain table and every query runs the full embedding scan (`vector_search_scan_filtered` + per-chunk fetch, source filter in Rust). `/system/status.retrieval` reports backend + latency. Slim the scan first, link sqlite-vec second (Phase 43 R43.9 → R43.10; the C amalgamation must compile on Windows MinGW). Python-era DBs carried a real vec0 table whose triggers broke every chunk write; migration 21 (R45.0, `drop_orphan_vec0`) removes it — never recreate vec0 triggers outside R43.10.
- **Single version source:** `rust/Cargo.toml` `workspace.package.version` via `scripts/sync_version.py` (note: `rust/scripts/sync_version.py` is an identical duplicate for `cargo run` from `rust/` — drift risk; CI `version-drift` watches it).
- **Job concurrency is bounded:** `jobs.rs` `MAX_CONCURRENT=2` globally; excess syncs persist as `pending` and queue. Per source, at most one `sync`/`reclassify` is pending/running (R30.1, guarded in `create_job`): explicit POSTs 409 with the live `job_id`, watcher/scheduler triggers coalesce silently. `embed` jobs are unguarded.
- **Label gate (B39/R35.1):** `sources.label` (internal|public|sensitive|pii) + provider trust — localhost always trusted, cloud needs `ANCHOR_CLOUD_TRUST=1`. Sensitive/pii sources are excluded from unconfirmed cloud answers (event recorded, refusal when nothing survives), skip cloud classify/embed, and skip follow-up rewrite. The R43.8 LAN bind gate refuses `0.0.0.0`+no-auth on bare metal (personal opt-out `ANCHOR_LAN_NO_AUTH=1`) but only warns inside containers, where 0.0.0.0 is mandatory and exposure is host-side `-p` (R43.29); Team refuses everywhere. `/qa/public` answers ONLY from `public` sources (MCP `public_only` mirrors it).
- **PII is people-driven (R35.1):** one manual whole-document mark (`ingested_items.is_pii`; `PATCH /items/:id`; Entities toggle; backup round-trips it). The B30 auto-detect stack is deleted, not deprecated — never reintroduce auto-flagging or a caller-asserted gate without an owner decision (`rust/docs/decisions.md` R35.1). `chunks.is_pii` columns are still in the schema but unwritten (drop is R35.3); marks are advisory + visible until R35.2 gates cloud flows.
- **`POST /sources` for Jira does NOT validate the instance** — config-only; only a sync fails on bad credentials. Fine for tests/onboarding.
- **Folder sync is incremental via stat fingerprints (migration 17):** mtime+size decide *whether to extract*, content hash decides *whether to reclassify*. Watcher compares via `list_files`, never `fetch`. NULL fingerprints (other connectors, old rows, imports) always extract once, then backfill.
- **Unreadable files are `skipped`, never purged** — keep new file types' error paths reporting, not dropping (sync once deleted PDFs because fetch skipped them).
- **File formats live in `extract.rs`:** folder + Drive both call `extract_file`/`extract_bytes` — plain-text kinds via `TEXT_EXTS`/`TEXT_NAMES`, real extractors for Word/PowerPoint/Excel+`ods`/`odt`/`odp`/`rtf`/`eml`/`pdf`/`html`, and diagrams (`drawio`/`dio`/`excalidraw`/`svg`, R46.2; `vsdx`/`vsdm`, R46.3; legacy `.vsd` unsupported like `.doc`) via `diagram_kind` — full-name match, so double extensions (`.excalidraw.json`, `.drawio.svg`) resolve first and their text is rendered markdown. Add new types there, never in a connector. Folder walking honors `.gitignore` (even outside git) and prunes `SKIP_DIRS` (only the watched root is exempt). Legacy `.doc`/`.ppt` deliberately unsupported.
- **Empty-string `app_settings` rows mean "unset"**: `non_empty()` reads `""` as `None` everywhere and `set("")` deletes the row. Never reintroduce `Some("")` — it makes relative-URL providers and flapping local/cloud labels.
- **PowerShell quoting:** a `"` in `git commit -m` breaks args (message lands as pathspec) — use `git commit -F <file>`; `git add <missing-path>` aborts the whole add — use `git add -A`. Never `Stop-Process chrome` broadly; chrome stdout goes to a file, not a variable.
- **PowerShell CI:** `curl.exe -o $null` passes an *empty filename* (exit 23 always) — use `-o NUL`; a `pwsh -command` step fails (exit 1) on a stale non-zero `$LASTEXITCODE` even after printing ok — assert statuses via `-w "%{http_code}"` and end steps with `exit 0` (broke v1.0.31 twice, 2026-10-19).
- **Skills are installed state, not source:** only `.agents/skills/` is tracked; the rest is gitignored and restored via `skills-lock.json`. Never `git add -A` them back.
- **Line endings are LF** (no `.gitattributes`; 0 CRLF files in the index) — if an edit fails to match, suspect whitespace/endings, not the tool. **Windows Rust builds use MinGW** (`winlibs` on PATH + `cargo +stable-x86_64-pc-windows-gnu --target x86_64-pc-windows-gnu --offline` from `rust/`; MSVC can't link). Fresh worktrees lack `rust/target` + `frontend/dist` (gitignored) — copy or rebuild.
- **Backup (Phase 25, `docs/backup.md`):** uid-based archives (never local ids), one-transaction import (dry-run = apply-then-rollback), secrets bundle decrypted *before* any write, `exports/safety-backup-*` never swept, imports queue an `embed` job (keyword-only until it runs). Keep the plan §7 grep test green.
- **Compile-time includes outside `rust/` must be copied into `hosting/Dockerfile`** (builder only takes `rust/` + `frontend/dist` + `.agents/skills/`) — R23.6's skill `include_str!` broke the team image build (exit 101) until the skills dir was added. Audit with `grep -rn "include_\(str\|dir\|bytes\)!" rust/crates/anchorcore/src` before tagging.
- **Cited entities attribute via the item:** entity chunks don't surface through TOC leaf search (`section_id IS NULL`), so attribute via `conflicts_for_chunks`, not the hit's `entity_id`. Anything that walks `relationships` as supporting evidence must skip adversarial kinds (`conflicts_with`).
- **Decisions/actions listings mirror `/qa/search` (R45.9):** `records_api.rs` resolves scope via `answer::project_scope` (+ `source_ids` intersect), drops rows through `retrieval::status_ok`, and withholds sensitive/pii-source rows under an untrusted answer provider (`blocked`, `refusal: "gated_provider"`, gate event). If owner decision §7.2.5 changes the search gate, change both together. Supersession is resolved both ways (`supersedes` on the newer record marks the older one `superseded`).
- **Chunker dispatch:** code splits by symbols (`chunk_code_with_sections`, `doc_type == "code"`, filename from `external_id`), configs split by key off `extract::is_config_filename` (not doc_type), markdown takes `markdown.rs` (extension-first, fence-aware, line ranges). Code/config keep raw text and skip extraction + cleaning via `skips_extraction` (markdown skips cleaning only). New splitters mirror `push_symbol`'s skip-empty-parent rule (no leading `" > "` paths).
- **Image bytes live in the DB (R46.7, `assets.rs`, migration 26):** `asset_blobs` (sha256 PK, GC triggers) + `assets` rows (`embed` on a hosting chunk, or `file` = an image file item). Never store a path reference or fetch later — export/backup must restore every image with the source gone (`assets/<sha256>` stored zip entries, hash-checked on import). Relative links resolve only inside the canonical folder root; no network on ingest. Sync never overwrites `manual_*` or `manual`/`ignored` attribution; the uid is deterministic (item uid + src + ordinal) so re-sync keeps it. Over `asset_max_bytes` = metadata row, NULL bytes, one warning — never a sync failure. Office/ODF images (R46.8) are `embedded:<zip part>` markers resolved from the doc package at sync (folder: the file on disk; Drive: the downloaded bytes on `IngestionDoc.package`, R46.15 — never a second download; pptx slides are `# Slide N` sections). Bytes are served at `GET /media/:uid` (R46.9, DB only, label-gated, CSP-sandboxed) — never mount anything API-side under `/assets/`: that prefix is the public SPA bundle dir (`auth::is_public_path`).
- **Rules extraction is the record parser (R45.8, `records.rs`):** decisions/actions come only from record structure (`Decision:` headings/fields, `Status:`, `Owner:`, ADR front matter, `Action items` bullets, checkboxes) — never prose sentences, table rows or fenced code. Record fields live in entity columns (migration 23: `record_id`, `record_status`, `due`, `done`, `supersedes`, `superseded_by`; backup round-trips them). **`verified` means a person confirmed it** — extraction always stores `unverified`; never reintroduce confidence auto-promotion.
- **Ingest is model-free (R45.18):** no LLM extraction, no distillation, no classifier settings. Never reintroduce a chat call on the ingest path without an owner decision (`rust/docs/decisions.md` R45.18); prose-level understanding is the agent's job at question time.
- **Extraction must go through `Classifier::classify` per window (R22.1)** — routing back through `classify_rules` fabricated decisions/actions from process docs in 1.0.10–1.0.14.
- **Two answer modes, one setting (R45.2):** `llm_mode` = `agent` | `local` (default `local`; read via `settings::llm_mode`). Agent mode makes zero chat calls on the answer path — `ask` skips rewrite + generation and returns `mode: "agent_compose"` (content-bearing citations, no warning); `answer_ready` is true without a model. `/qa/search` never depends on the mode. Agents reach AnchorCore over MCP *or* the REST skill — no feature may be MCP-only. `agent_compose` must never warn (MCP `fallback_ask_warning` included).
- **`/qa/search` hits carry provenance + opt-in verbatim content** (`include_content` ≡ `fields: content`; MCP caps 4000 chars + `content_truncated`). `path` = section breadcrumb else the item's `external_id`.
- **The embedding backfill (`scheduler.rs`, startup + 15 min) is deliberately ungated** — it drains NULL vectors (IDF-skipped chunks would otherwise stay NULL forever). Don't gate it; backup-import re-embed stays gated.
- **Vectors carry provenance; never compare across families (R45.5, migration 22, `embed_fp.rs`):** every chunk-vector write must stamp `chunks.embed_fp` (`provider:model:dim`) — `Embedder::sync_vec` does it, so new write paths call it (a replaced vector must never keep the old stamp). `embed_query` records the query fingerprint in `embed_state` before retrieval; vector legs filter via `append_vector_family_filter`. Out-of-family/unstamped vectors are keyword-only and the backfill re-embeds them (also woken by `Embedder::family_changed`). Shared families are an explicit allowlist (`SHARED_FAMILIES`) — add a model there only with measured parity.
- **Logging is stdout + rotating file** (`{data_dir}/anchorcore.log`, 10 MB × 3, `RUST_LOG` overrides). Windowed builds have no console — dropping the file layer silences everything but panics.
- **Job totals are set by the run phase, not `finish_job`** (`total` = scanned, `processed` = walked; `result.items` is only the changed subset).
- **The update check is manual-first:** plain `GET /system/update` serves cache only; `?refresh=1` or the explicit startup opt-in hits the network. Don't add a boot check outside the opt-in (`docs/updates.md`).
- **Test-env handling is live-first ordering** (`prefer_live_envs` stable-partitions before every cut; the ×0.5 only shapes scores). Env classifies per item via path markers / fixture-grade file-head vocabulary only. Queries naming test files are exempt; `ANCHOR_TEST_ENV_DEMOTE=1.0` disables. Explicit filenames still win over env.
- **Final hits are leaf chunks with match-centered previews:** summary chunks are TOC internals and never surface as evidence; snippets window on query terms (`…`-marked). Sibling expansion claims bytes in rank order (`[continued]`), never repeating them.
- **Item discovery is `GET /items`, drill-down `GET /items/:id`** (metadata-only list; `path_prefix` + `source_id` + limit/offset). Every content payload exposes `content` (`text` stays as canonical alias). Entities carry `chunk_id` next to `item_id`.
- **Tray on macOS needs `NSApplication` first** (`tray.rs` `init_appkit` — bare `NSStatusBar` aborts, exit 134) **on the main thread**; gate with `--no-tray`/`ANCHOR_TRAY=0`. Linux is a stub — never add tray system libs to Linux CI. Failures fall back to tray-less; the server always runs (`docs/tray.md`).
- **Lizard 1.24 mis-scopes two Rust patterns** (non-ASCII char literals like `'ƒ'`, and `matches!(c, 'i' | 'v' | …)` alternative lists): the tokenizer swallows the rest of the file into one function's span, hiding real CCN and flagging untouched functions. Fixed behavior-identically (`\u{XXXX}` escapes, `"ivxlcdm".contains(...)`). If lizard flags a function your diff never touched, suspect the tokenizer and check spans before believing it. (`rtf_to_text` CCN 31 is filed as R36.14; the `text_decodes_*` span is a proven artifact.)
- **Purged names stay purged — never write them back, not even in verification specs.** The 2026-10-13 purge rewrote history repo-wide; describe purged content by count/date only. Grep patterns for re-verification are owner-held, not stored in-repo.
- **PDF extraction is adaptive, not single-pass:** `extract_pdf` keeps the standard output unless the split-word detector trips (unknown 2–4-char fragments + rejoinable pairs vs vendored `pdf_words.txt`, ≥6 and ≥6‰), then runs the `PdfFlowOutput` repair (gap joins incl. Word's width-0 glyphs, para breaks, dehyphenation) which wins only on strict improvement. Repairs warn + record `system_events`; ties stay debug-level. Force re-sync re-extracts indexed PDFs.
- **B12 cleaning is prose-only:** `clean_doc_text` runs only when `!skips_extraction()` and not markdown (collapsing whitespace destroys code/config/markdown structure). `chunk_text` snaps window ends to sentence/word boundaries; `classify_windows` keeps the blind loop.
- **One-shot migration backfills live in real `M::up` SQL, never `ensure_columns`** (which re-runs every boot). Extend the v10-sim migration test per migration (drop the artifact, bump the version assert).
- **Fusion weights are structural (Phase 39; details in the tuning guide):** TOC@1.0 vs floors@0.5 locks floor-only hits out whenever TOC returns 8+ — fixed by slot reservation (R39.2 keyword, R40.4 type), never by re-tuning weights. Hits carry leg provenance; empty evidence gates on BM25/boost/cosine≥0.50; decay floors at 0.8; `filename_boost` runs post-cut, scope-filtered (R43.1); authority tiers sort (env,tier) after live-first (`ANCHOR_AUTHORITY_TIERS=0` kills); ask+search+eval share `orchestrate_fusion`. Search `k` widens to `max(k, cursor+limit)` (R40.1); slot scores are the floor leg's RRF share (R40.2); TOC suppression is a sliding window, chunk-time only (R40.3).
- **Vocabulary is people-owned, never proposed (R45.13, reverses R40.7/R40.8):** three origins, all `active` — `manual` (typed in via `/glossary`, global), `glossary` (rows of a file a person marked with `PATCH /items/:id {"is_glossary": true}`, parsed at once and on re-sync), `rule` (`Full Phrase (FP)` parentheticals that pass `is_initialism` only — code tables and glossary-shaped lines are never auto-extracted). Never reintroduce LLM `defined_terms`, a proposal status, or a review queue without an owner decision. Agent mode skips `rule` rows (glossary still applies); local mode may widen the *retrieval* query with model acronym expansions (`query_expand.rs`: unknown acronyms only, one cached call, opt-in via `acronym_expansion=true`, nothing stored). Query merge is project-scoped (`fts_match_query_scoped`; manual rows apply in every scope); pure `fts_match_query` stays curated-only. Backup round-trips vocabulary rows + the item mark.
- **Heading-prefixed vectors are uniform since R38.2, not markdown-only:** all three embed paths call `embed_input(chunks.path, content)` — "bare" vectors mean empty-path chunks (undetected structure) or pre-1.0.28 rows (stay bare until force re-sync; no silent mass re-embed). Continuation chunks (heading in path, not in bytes) are the main winners — pair `rfp-escrow-01` pins it.
- **Sync completion is two markers:** `content_hash` (stored) vs `processed_hash` (fully finished). `store_doc_chunks` delete+insert is one manual `BEGIN IMMEDIATE`/`COMMIT` (`run_db` hands out `&Connection`, so no `conn.transaction()` — early `?` rolls back on drop).
- **Markdown chunks by blocks** (`markdown.rs`, hand-rolled CommonMark subset — no new deps): fence-aware blocks with 1-based line ranges, heading tree, whole-block packing. Breadcrumb + link-stripped text on all three embed paths, but the IDF gate stays on raw content — don't merge them back. Old rows/archives read `0/0` line ranges.

## UI notes

- `App.tsx` — tabs + header (project picker scopes Ask); mounts `OnboardingWizard` on first launch with no sources (dismissable via `localStorage`).
- `OnboardingWizard.tsx` — mode choice (who writes answers) + Ollama checks → connect a folder or the bundled `sample/` corpus (dev checkout only; packaged apps report unavailable) → ask with cited answer.
- `FolderPicker.tsx` — folder browser (`GET /system/fs`: child dirs only, no canonicalization). Keep the typed-path input.
