How it works

1.1

Connect what you already have

A folder or Obsidian vault, Google Drive, Jira, Linear, Miro, or any JSON API. PDFs, Word, Excel, Markdown and diagrams are read as they are. It re-syncs on its own; nothing moves.

1.2

Indexed by section

Documents are split at their headings, and decision records keep their owner, status and what they replace. All of it sits in one database on your disk.

1.3

Answers point at the passage

Ask in the browser or from your coding agent. Every answer lists its sources down to the section and line range, so you can open the page and check.

Who writes the answer

A local model, in the app

Download, open it, add a folder, ask. A local model writes the answer, or switch to agent mode and the app shows the cited passages your agent gets. It runs at 127.0.0.1:8000 with no account and no Docker. Try it on the sample company first.

Your coding agent

Claude Code, Codex, opencode and Cursor search your files over MCP or the local REST API and write the answer themselves, so the app needs no chat model. The setup skill installs the app, connects folders and checks the first cited answer.

What leaves your machine

Your index stays on your machine, and answers are generated locally unless you connect a cloud model. Below is everything the app can talk to, read from the source. Full security notes.

No telemetry

The app contains no analytics, usage tracking or crash-reporting code. The source is public, and the only outbound calls are the ones listed here. Read the source.

Works offline, within limits

With a local Ollama model and folder sources, everything runs with Wi-Fi off. Connectors, cloud models and update checks need a network.

Sensitive sources are gated

"Approved" means a local endpoint, one you list in ANCHOR_TRUSTED_PROVIDERS, or ANCHOR_CLOUD_TRUST=1. Sensitive and pii sources also skip cloud embedding. pii is a source label you choose; the separate per-document PII mark is manual and advisory today. Public sharing and agent public_only mode see only sources you marked public. Nothing is detected as PII automatically, and there is no SSO or role system in the local app.

FAQ

Do I need Ollama?

No. Without a model you still get full-text search, and in agent mode your coding agent writes the answer from AnchorCore's cited results. Add Ollama (one install, free models) to get answers inside the app.

How is this different from NotebookLM or ChatGPT file search?

Those are cloud uploads. AnchorCore runs on your machine, connects to folders, Drive, Jira, Linear, Miro and APIs, and keeps sources you marked sensitive away from AI you haven't approved. Full comparison with NotebookLM.

Does it stay fast as my library grows?

It narrows thousands of documents to the few relevant sections via tags and summaries, then searches only those. Measured at ~7ms per search on a 30k-chunk benchmark (results, script); larger libraries are projected, not yet measured.

Can I move to a new computer?

Yes. System → Backup & restore exports your whole index into one portable .anchorcore-backup file. Credentials stay behind unless you opt into the passphrase-encrypted bundle. Backup guide.

Is it open source?

It is source-available: the repository is public, so you can read what the app does or build it yourself. Personal use is free; team and commercial use need a license. See LICENSE.md.

First launch

The builds are not yet Apple-notarized or code-signed, so your OS asks once. macOS: move AnchorCore to Applications, open it, then System Settings → Privacy & Security → Open Anyway. Windows: SmartScreen → More info → Run anyway.

Verify the file

Each release has a SHA256SUMS file next to the zips. Put it in the same folder as your download and run shasum -a 256 -c SHA256SUMS --ignore-missing (on Windows, compare Get-FileHash with the matching line). Release notes.
