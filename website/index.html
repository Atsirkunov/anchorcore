Proof it stays on your machine

Your index stays on your machine. Answers are generated locally unless you connect a cloud model. Here is everything the app can talk to, read from the source rather than promised.

No telemetry

The app contains no analytics, usage tracking or crash-reporting code. Check it yourself: the source is public, and the only outbound calls are the ones in the diagram. Read the source.

Works offline, within limits

With a local Ollama model for both indexing and answers, and folder sources, everything runs with Wi-Fi off. If answers use a cloud model, they need a network. Connectors (Jira, Linear, Drive, REST), cloud models and update checks need a network.

Sensitive sources are gated

Source labelLocal modelApproved cloudUnapproved cloud
internal (default)✓✓✓
public✓✓✓
sensitive✓✓✗ held back, audited

"Approved" means a local endpoint, one you list in ANCHOR_TRUSTED_PROVIDERS, or ANCHOR_CLOUD_TRUST=1. Sensitive sources also skip cloud classification and embedding. Public sharing and agent public_only mode see only sources you marked public. There is no automatic PII detection and no SSO or role system in the local app.

Verify your download

Each release carries a SHA256SUMS file next to the three zips. Download it into the same folder as your zip, then:

macOS / Linux:  shasum -a 256 -c SHA256SUMS --ignore-missing
Windows:        Get-FileHash .\AnchorCore-windows.zip -Algorithm SHA256
                (compare with the matching line in SHA256SUMS)

Signing status: the macOS app is ad-hoc signed and not Apple-notarized; the Windows and Linux builds are not code-signed; nothing is store-signed. That is why the first launch needs the "Open Anyway" / "Run anyway" step above. The checksum shows the file is the one the release published; the source is public so you can build it yourself. FAQ

Is my data private?

Yes. The app only listens on your own machine, keeps everything in a database on your disk, and stores passwords in your OS keychain (macOS, Windows) or an encrypted local file. Sources you mark Sensitive are never sent to cloud AI unless you explicitly approve that provider.

Can I move to a new computer?

Yes. System → Backup & restore exports your whole index — sources, entities, review state — into one portable .anchorcore-backup file. Import it on the new machine (preview the dry run first); credentials stay behind unless you opt into the passphrase-encrypted bundle. Full guide: Backup, export & device migration.

Can I check the code myself?

Yes — AnchorCore is source-available. The repository is public: read exactly what the Rust app does (no telemetry; it only contacts endpoints you configure) or build it yourself. Personal use is free; team and commercial use need a separate license — see LICENSE.md.

How does it read documents?

It splits documents at their headings (§4.2, 3.1.1, Article 12…) and packs the text into short passages. Each section gets a summary and topic tags, so answers cite the exact section — not “somewhere in the PDF”.

Does it stay fast as my library grows?

Yes. It narrows thousands of documents to the few relevant sections via tags and summaries, then searches only those. Measured at ~7ms per search on a 30k-chunk benchmark (results, script); larger libraries are projected, not yet measured.

Is it free?

Personal local app — free. Team self-hosted (one Docker container, your VPC) is quote-based — request a quote. Hosted is coming soon — join the waitlist.

Do I need Ollama?

No. Without it you still get full-text search over everything. Add Ollama (one install, two free models) for AI answers with citations.

Citations you can click?

Every answer lists its sources with section links like Art 12 › 12.3 — click to jump to the passage. Coding agents get the same cited format.

How is this different from NotebookLM or ChatGPT file search?

Those are cloud uploads. AnchorCore runs on your machine, connects to folders, Drive, Jira, Linear and APIs — not just uploads — and never sends sources you marked sensitive to AI you haven't approved.
